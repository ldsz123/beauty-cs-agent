## 补齐电商客服 Agent 到生产级实战落地标准

基于全面评估，需要在三个核心维度补齐差距：**安全性**、**测试体系**、**可观测性**。以下是具体实现方案。

---

### 一、安全性加固

#### 1.1 API 认证 + Rate Limiting

**新增文件：**
- `src/middleware/auth.py` — API Key 认证中间件
- `src/middleware/rate_limit.py` — 基于 Redis 的滑动窗口限流器

**修改文件：**
- `src/main.py` — 添加认证依赖、限流中间件、CORS 白名单
- `requirements.txt` — 添加 `slowapi`（限流）

**具体实现：**
- 所有 `/api/*` 端点（除 `/api/health`）需要 `X-API-Key` 请求头
- 通过环境变量 `API_KEYS` 配置多个有效 key（逗号分隔）
- 限流：每 IP 每分钟 60 次请求，每 session 每分钟 20 次
- CORS 改为从环境变量 `ALLOWED_ORIGINS` 读取，默认仅允许同源

#### 1.2 输入验证 + Prompt Injection 防护

**修改文件：**
- `src/main.py` — ChatRequest 添加长度限制、内容过滤
- `src/agent_engine.py` — 用户消息在拼入 LLM prompt 前做转义

**具体实现：**
- `message` 字段限制 1-2000 字符
- `session_id` 限制为 UUID 格式或字母数字
- 图片上传限制：最大 5MB，仅允许 JPEG/PNG/WebP
- 用户消息中的 `"""`、`###`、`---` 等 prompt 分隔符做转义
- 添加 `src/utils/sanitizer.py` 统一处理输入清洗

#### 1.3 密钥管理

**修改文件：**
- `.env.example` — 移除硬编码密码，改为占位符
- `docker-compose.yml` — 移除默认密码 fallback
- `config/config.yaml` — 移除 debug: true

**具体实现：**
- 所有密码/密钥改为 `change-me` 占位符
- Docker Compose 中密码无默认值，必须从环境变量传入
- 生产环境强制要求 `DEBUG=false`

#### 1.4 Redis 认证

**修改文件：**
- `docker-compose.yml` — Redis 添加 `--requirepass`
- `config/config.yaml` — Redis URL 支持密码

---

### 二、测试体系

#### 2.1 pytest 基础设施

**新增文件：**
- `pytest.ini` — pytest 配置（asyncio_mode、testpaths、cov 配置）
- `tests/conftest.py` — 共享 fixtures（mock LLM client、test config、async session）
- `tests/mocks/llm_mock.py` — Mock LLM 客户端

**具体实现：**
- `asyncio_mode = "auto"` 自动识别 async 测试
- 配置 coverage 阈值 60%
- Mock LLM 返回预设的 JSON 响应，覆盖情感/语义/实体/回复生成

#### 2.2 核心模块单元测试

**新增文件：**
- `tests/test_agent_engine.py` — Agent 引擎完整流程测试
- `tests/test_session_manager.py` — 三种模式会话管理测试
- `tests/test_knowledge_base.py` — 知识库检索测试
- `tests/test_action_executor.py` — 业务动作执行测试
- `tests/test_llm_client.py` — LLM 客户端测试
- `tests/test_api.py` — API 端点集成测试（使用 httpx ASGITransport）

**具体实现：**
- 每个测试文件覆盖对应模块的公共方法
- 使用 mock LLM 替代真实 API 调用
- 测试正常路径 + 异常路径 + 边界条件
- API 测试使用 `httpx.AsyncClient(transport=ASGITransport(app=app))`

#### 2.3 CI/CD 流水线

**新增文件：**
- `.github/workflows/ci.yml` — GitHub Actions 工作流

**具体实现：**
- 代码检查：`ruff` lint + `mypy` 类型检查
- 运行 pytest + coverage
- 覆盖率低于 60% 则失败
- Docker 构建验证

### 三、可观测性

#### 3.1 结构化日志

**新增文件：**
- `src/utils/logging_config.py` — loguru 配置（JSON 格式、文件轮转、请求 ID）

**修改文件：**
- `src/main.py` — 添加请求 ID 中间件，注入 log context
- `src/agent_engine.py` — 关键步骤添加结构化日志字段

**具体实现：**
- 日志输出 JSON 格式（`logger.add(sys.stderr, format=..., serialize=True)`）
- 每个请求生成 `request_id`，通过 `logger.contextualize()` 注入
- 关键日志包含：`session_id`、`user_id`、`processing_time_ms`、`intent`、`emotion`
- 文件日志：`logs/app.log`，按天轮转，保留 30 天

#### 3.2 Prometheus Metrics

**新增文件：**
- `src/middleware/metrics.py` — Prometheus 指标中间件
- `src/utils/metrics.py` — 指标定义和收集

**修改文件：**
- `src/main.py` — 挂载 `/metrics` 端点
- `requirements.txt` — 添加 `prometheus-client`

**具体实现：**
- 指标类型：
  - `http_requests_total` (counter) — 按 method/path/status 分组
  - `http_request_duration_seconds` (histogram) — 请求耗时
  - `llm_calls_total` (counter) — 按 provider/model 分组
  - `llm_tokens_total` (counter) — token 消耗
  - `pipeline_stage_duration_seconds` (histogram) — 三级流水线各阶段耗时
  - `active_sessions` (gauge) — 活跃会话数
  - `escalations_total` (counter) — 转人工次数

#### 3.3 健康检查改进

**修改文件：**
- `src/main.py` — 重写 `/api/health` 端点

**具体实现：**
- 区分 liveness（进程存活）和 readiness（依赖就绪）
- `/api/health` — liveness，始终返回 200
- `/api/health/ready` — readiness，检查 DB/Redis/LLM 连通性
- 状态码：全部就绪 200，部分降级 503
- 响应包含每个依赖的状态详情

#### 3.4 异常处理

**新增文件：**
- `src/exceptions.py` — 自定义异常类
- `src/middleware/error_handler.py` — 全局异常处理器

**修改文件：**
- `src/main.py` — 注册异常处理器

**具体实现：**
- 自定义异常：`ValidationError`、`RateLimitExceeded`、`LLMError`、`StorageError`
- 统一错误响应格式：`{"error": {"code": "...", "message": "...", "request_id": "..."}}`
- 未捕获异常返回 500 + 错误码，不暴露内部细节

#### 3.5 优雅关闭

**修改文件：**
- `src/main.py` — 改进 lifespan 关闭逻辑
- `src/models/llm_client.py` — 添加 `close()` 方法

**具体实现：**
- 关闭时先停止接收新请求（通过信号量）
- 等待进行中的请求完成（最多 30 秒）
- 关闭 LLM 客户端连接池
- 关闭数据库连接池
- 关闭 Redis 连接
